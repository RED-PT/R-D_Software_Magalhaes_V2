# Reference

Function-level documentation for every public API in the firmware.
Hand-curated, organised by module, cross-linked to the concept pages
that explain *why*. Each page covers:

- **Public types** — structs, enums, and the meaning of each field.
- **Functions** — full signatures with parameter direction
  (`[in]` / `[out]` / `[in,out]`), return value, preconditions, and
  failure modes.
- **Examples** — the same patterns used in the firmware itself.
- **Cross-links** — into the concept pages and the auto-generated
  Doxygen output.

If you want every symbol indexed by name, see the
[auto-generated reference](/api/index.html).

## Conventions

- **`[in]`** parameters are read by the function and not modified.
- **`[out]`** parameters are written by the function. Pass a pointer
  to caller-owned storage.
- **`[in,out]`** parameters are read and modified.
- **`true` on success** is the firmware-wide convention for `bool`
  returns. `false` means the call failed; the function will `printf`
  a diagnostic.
- **`HAL_StatusTypeDef`** returns are passed through unmodified from
  the underlying STM32 HAL.
- **`__attribute__((packed))`** on structs that go on the wire — do
  not reorder fields.
