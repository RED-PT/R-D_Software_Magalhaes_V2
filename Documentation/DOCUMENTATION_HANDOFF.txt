 0. THE ONE-LINE GOAL
--------------------------------------------------------------------------------

Build a documentation site for the Magalhaes flight computer firmware that
looks and feels like Shopify's Liquid docs (https://shopify.dev/docs/api/liquid):
clean, narrative, code-grounded, with two-pane "input/output" code blocks and
a curated reference instead of raw Doxygen.

  - "I want everything in the website. ... how every single thread works and
    how the communications work. everything"
  - "I want the same colors as shopify website"
  - "This need to tell a history almost. ... make something awesome."
  - "the API is horrible" (referring to default Doxygen output -> demoted
    to a 'Source ↗' link in the top nav, no longer the primary API ref)

       The marquee narrative. Walk through one rocket flight chronologically,

         t = -inf   Power on -> hal_callbacks runs, FreeRTOS starts,
                    create_threads.c spawns 8 threads. Controller and
                    Estimator are CREATED SUSPENDED.
         t = 0      STATE_BOOT. fsm_init prints banner. Sensors thread
                    starts polling. SD thread mounts the card and opens
                    flight_<n>.bin. Radio thread starts listening for sync.
         t = 30s    Calibration: ground-pressure baseline captured by
                    estimator's first BARO_t reads. fsm_get_baro_calibration.
         t = 60s    GS sends SET_PROFILE then ARM. FSM resumes Controller
                    + Estimator threads. PWM_ArmESC(2000) plays ESC tone.
         t = T-0    LAUNCH command. STATE_FLIGHT entered. Estimator's
                    check_flight_events sees accel spike -> FSM_EVT_LIFTOFF.
         t = T+1s   Telemetry frame 1: telemetry_fast_t at 8 Hz over slot
                    0..7, telemetry_slow_t at 1 Hz over slot 8.
         t = apogee Vario crosses zero -> FSM_EVT_APOGEE. Controller mode
                    switches to LANDING. PID drives velocity toward
                    -touchdown_velocity_ms.
         t = flare  altitude < flare_altitude_m -> FSM_EVT_FLARE_ALT.
                    Throttle ramps up.
         t = touch  Accel impact spike -> FSM_EVT_TOUCHDOWN, then accel +
                    altitude stable for N seconds -> FSM_EVT_LANDED.
         t = post   STATE_SAFE entry. sd_card_close flushes + unmounts.
                    Telemetry continues at slow rate. Log file is
                    flight_<n>.bin, decode with Dashboard Python/decode_log.py.

       Style: Use <CodeDemo> blocks to show actual log output alongside
       firmware code. Drop in <FuncRef> pills inline.

 7. CONVENTIONS WORTH PRESERVING
--------------------------------------------------------------------------------

  - File frontmatter: every .mdx starts with `--- title: ... ---`. Used by
    Nextra for the <title> tag and breadcrumb.

  - Imports: each .mdx imports only what it uses, e.g.
        import { Callout } from 'nextra/components';
        import { CodeDemo } from '../../components/CodeDemo';
        import { FuncRef } from '../../components/FuncRef';
    (Path depth differs per folder - 1 ".." for /pages, 2 for nested.)

  - Function references: link out to the Doxygen-generated /api/ pages with
    <FuncRef name="..." file="..." /> instead of inventing new anchors. Keeps
    the curated docs synced with whatever Doxygen actually generates.

  - Param convention: [in], [out], [in,out] tags in C-block param tables -
    matches Doxygen's vocabulary so a reader can move between curated +
    auto-generated views without context switching.

  - Code blocks must include a `title=` attribute pointing at the actual
    source file, e.g. ```c title="Codigo/Storage/sd_card_thread.c". This
    keeps the docs auditable - a reader can grep the title and confirm.

  - DON'T duplicate Doxygen. If a struct/function is fully self-evident from
    its declaration, just link to /api/. Reserve curated prose for things
    Doxygen can't express: design rationale, threading invariants, byte-level
    on-the-wire formats, why-do-we-do-it-this-way.
